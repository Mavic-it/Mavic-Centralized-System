# Tasks and Incidents interface refresh

Scope: `/tasks`, `/incidents`, their create/detail drawers and matching loading states. Follow `.ai/skills/SKILL.md` within the existing brand and Phase 1 boundary. No API, schema, permission, case-audience or workflow changes.

Audit: the list is table-only, statuses share one neutral treatment, there is no visible-record search/sort, detail actions compete with a long activity/file list, and native file fields provide little selection feedback. Existing submission, private evidence and server authorization remain the foundation.

Design: use responsive cards with a compact table option; status and priority colors with text labels; search/sort explicitly limited to the current page; existing server status/personal/team filters and pagination. Show no invented global counts. Detail drawers separate overview, authorized activity, files and update forms using keyboard-operable tabs. An overview surfaces the current state, actual task progress and relevant next action without submitting anything automatically. Preserve unfinished forms while switching tabs. Create forms gain clear grouping and selected-file/drop feedback; existing file size/type/atomic-save rules remain.

Validation: focused search/sort/presentation and existing action/proxy tests, TypeScript, ESLint and production build. Artificial-data actual-component browser checks cover cards/table/search/sort, status selection, drawer tabs and keyboard navigation, progress editing, private notices/responses, optional create files/drop/remove/retry, empty/error/loading states and 320/360/768/1024/1440px layouts. No real task, incident, notification or evidence writes.

Implemented shared components: `record-collection.tsx` (cards/table, search, sorting, local group filters, matching card skeletons), `detail-overview.tsx` (state, metadata, progress and next action), `work-tabs.tsx` (roving focus and arrow/Home/End navigation), `attachment-picker.tsx` (native picker, drop/select/remove feedback and bounded single-file choice), `progress-editor.tsx` (synchronized slider and percentage), and `presentation.ts` (date/overdue/status/search/sort helpers). `workspace.tsx` retains the existing queries, mutation contracts and confirmation flow. Detail forms stay mounted between tabs; successful updates reveal their history with focus on Activity. Errors remain visible across drawer sections. Table positioning is contained in its own scroll region on narrow screens. Existing CSS form primitives and scoped module styles share the restrained brand palette.

Final checks: 11 focused frontend tests passed; TypeScript, ESLint and the production Webpack build passed. Chrome fixtures passed 163 main checks plus 10 supplemental checks, with no runtime exceptions. Verified five widths, card/table layout, accented-name search helpers, sort order, server status-filter requests, one visible detail panel, keyboard navigation, retained drafts, drag/drop/remove, original create payloads, slider updates, receipt/explanation flow, confirmation cancellation/saving, optional no-file creation, role controls, unavailable IT role, empty/error/loading states and reduced motion. Mobile/desktop screenshots were inspected under `tmp/work-modules-review`. Browser responses and writes were intercepted using artificial records; authenticated business mutations were not performed. No API/schema or phase change.
