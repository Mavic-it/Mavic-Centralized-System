# Optional leave supporting documents

Employees can attach one optional medical certificate or other proof when creating or editing a pending request. Accepted files are PDF, JPG/JPEG and PNG, up to 5 MB. Empty selection preserves an existing document; a new file replaces it. Existing leave policy, balance, date and approval validation still applies. Approved/rejected/cancelled requests remain read-only. This targeted user-requested leave extension does not open another HRIS phase.

The existing request form owns the native optional file input. The workspace sends multipart only when a file is selected and keeps the form/file selection on failure. The shared request drawer shows the filename and an authenticated download link in My Leave and Leave Management, with a clear missing-document state. No file bytes or storage URLs are included in list responses. Server-side ownership and branch-scoped reviewer access protect downloads; IT administrators have no reviewer access solely from their role.

The API supports JSON requests as before and multipart `document` on POST `/leaves` and PATCH `/leaves/:id`. Extension, MIME, signature, nonempty content and size are checked server-side. Request changes and document storage share the existing database transaction. Supporting file metadata/bytes are stored in `leave_request_documents`, one row per request, with request/user foreign keys, bounded bytes and an upload audit event. Authenticated GET `/leaves/:id/document` returns an attachment with private/no-store, nosniff and sandbox headers. Legacy `attachment_url` values are retained and are not treated as trusted download URLs.

Deploy migration `1792454404000-LeaveSupportingDocuments` before the new API/web code. It adds a table without altering existing request rows. The local migration was applied explicitly with other pending migrations excluded. Avoid automatic schema synchronization. There is no destructive down migration: preserve uploaded medical records and use a reviewed forward migration for recovery. Replaced files are overwritten; document version history and automatic retention deletion are outside this feature.

Verification includes file validation, ownership/role/branch restrictions, keeping/replacing pending proof, byte-preserving proxy uploads/download headers, and PostgreSQL byte/foreign-key/size/uniqueness/cascade checks in rollback-only temporary fixtures. Browser checks use artificial documents and deliberately rejected saves, not real medical records.
