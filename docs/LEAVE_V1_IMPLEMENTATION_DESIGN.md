# Simple leave implementation design (2026-10-22)

The latest user request re-enables only this leave slice. Main HRIS Phase 1 remains active. The retirement migration and recovery file are historical; no old grants or requests are silently restored.

1. Component tree: authorized server routes > LeaveWorkspace (query orchestration and context) > MyLeave/Requests/BalanceWorkspace/LeaveSettings/LeaveReports. RequestForm and RequestDrawer own filing and review dialogs. Reuse Modal, confirmation provider, buttons/inputs, skeletons, status badges and sidebar primitives. LeaveSettings owns versioned policies plus employee eligibility assignments in dialogs.
2. Responsibilities: API alone owns identity, scope, schedule days, eligibility, credits, allocation and transitions. Browser owns filters, form drafts, selection, modal state and previews from the API. Reports contain no leave reasons. A separate shared leave-attendance adapter integrates approved units into DTR without importing transport code.
3. Contracts: typed context, policy, balances, requests, paged list, preview, detail/events and report responses. Strict DTOs reject unknown/array values. Dates are YYYY-MM-DD in Asia/Manila; days use NUMERIC and half-day increments. Files reuse bounded PDF/PNG/JPEG storage patterns. Errors are actionable strings. Server derives employee/branch/days and policy snapshots.
4. State: React Query handles server state and invalidation after mutations. URL filters support report drilldown; local forms/dialogs never act as authorization. All operations include loading, empty, error/retry, unauthorized, disabled/pending and success feedback. Decisions, cancellation, allocations and adjustments require confirmation. Explicit idempotency keys survive retry within the form.
5. Visual system: existing Mavic workspace tokens, restrained red primary actions, white cards, clear heading/description/action hierarchy, compact filter rows, legible amounts and semantic status text. My Leave emphasizes available credit then filing/history. Admin has exactly four destinations, with settings hidden from managers. Tables scroll within their container and cards/grids stack on narrow screens. No decorative motion or new chart library.
6. Accessibility: semantic headings/tables/forms/buttons, visible focus, labelled filters, textual chart values, keyboard links, Modal focus trap/restoration and Escape/busy guards. Validation uses alerts; previews use polite live regions. No color-only status and no added animation; respect reduced motion and 200% zoom.
7. Files: API hr/leaves/{leave.types,leave.dto,leave.policy,leave.service,leave.controller,leave.allocator}.ts; shared hr/attendance/approved-leave.ts; additive migration 1792627202000-SimpleLeaveV1. Web app/leave/{types,api,ui,workspace,request-form,request-drawer,balances,settings,reports,leave.module.css}; five server routes/loading shells, API proxy, sidebar/access changes. No duplicate employee/auth tables. Policies use immutable versions; credits are an immutable signed ledger, with unique sources and employee row locks.
8. Verification: policy/DTO/scope/navigation tests, real PostgreSQL isolated-schema transactions including concurrent overspend/decisions, annual grant retries and adjustment/cancellation behavior; matching preview/charge/balance/report arithmetic and CSV/XLSX safety; DTR integration; production builds, lint/types and browser checks at narrow/wide sizes. Record remaining operational checks honestly.

V1 choices: each request stays within one calendar credit year (split cross-year ranges); no carryover; annual/manual allocation only. SIL requires an explicit HR assignment confirming eligibility/equivalence. Annual grant keys remain stable across policy edits to avoid doubling a year's credits; later corrections use adjustments. New example types are inactive. Automatic allocation is opt-in and uses an authorized scheduler actor; newly eligible/onboarded staff are picked up on the next controlled run.
