# Notification navigation

Each notification stores an optional internal destination. Clicking its title, message or timestamp follows a native Next Link, closes the notification modal and attempts to mark the notification read. The separate Mark as read action remains available. Read failure does not prevent navigation and unread notifications remain retryable.

Password recovery links open the authorized reset queue with a requestId query parameter and automatically open its right-side detail panel, including completed requests. Leave decisions link to My Leave with the corresponding requestId and open its existing drawer. Missing or no-longer-accessible records show a clear message; destination APIs keep existing authorization and branch rules.

An additive migration preserves notifications and backfills recognized leave destinations. Historical recovery alerts are matched by their transaction timestamp to an unambiguous reset request, falling back to the reset queue when matching is impossible. Informational notifications without a destination remain readable. Links accept only internal paths and never external URLs. Phase 1 remains active.

Recovery detail layout (2026-10-21): recovery details use a nonmodal right-hand panel alongside the list, with independent scrolling on desktop and details stacked above the list on narrow screens. Notification deep links select the same panel. Existing review actions and busy guards remain.

Removed the split layout so the queue retains its full width behind the drawer. Stronger drawer selector specificity prevents shared modal styles from centering or rounding the drawer. Existing busy guards, Escape/backdrop handling, focus restoration and notification deep links are preserved. Phase 1 remains active.
